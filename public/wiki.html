Spirits & ranks

Every public repository you own becomes a spirit. Commits make it evolve. Your whole jungle earns a canopy rank. Here is exactly how it all works.

Spirits

Five stages of evolution

A spirit's stage comes from the commit count on its repository's default branch. Its soul light, eyes and lantern flame take the repository's GitHub language color.

Canopy rank

Seven ranks of the canopy

Your rank estimates where your profile sits among GitHub users. It blends four signals from your public, non-fork repositories.

How the rank is calculated

Each signal is turned into a value between 0 and 1 with a cumulative distribution centred on a typical (median) value. A profile exactly at the median scores 0.5 on that signal.

SignalMedianWeightCurve
 
exponential(x) = 1 − 2^(−x)
log-normal(x)  = x / (1 + x)          where x = value ÷ median

score  = Σ (weight × curve) ÷ Σ weight
top %  = (1 − score) × 100

Stars carry the most weight because they are the strongest public signal that other people value your work. Commits come next. Followers and the number of repositories add context. The grade is the first rank whose threshold contains your top %.

This is an estimate built from public data. It is not an official GitHub statistic.

Counting

Where the numbers come from

Spirits

Every public repository you own, excluding forks. The README image shows the top 10 by default. Use limit=20 (any number) or limit=all for every repository, up to 36 in the image and 60 in the playground. sort decides which come first: commits, stars or updated.

Commits

The exact number of commits in each repository's default-branch history, summed across your repositories. That includes commits by collaborators. With a server GITHUB_TOKEN this comes from one GraphQL query. Without one, each count is read from the GitHub REST API. If the anonymous rate limit runs out, the remaining counts are estimated and marked with ~.

Stars & forks

Stargazers and forks summed across your public non-fork repositories. Very large accounts are read up to the 200 most-starred repositories, which covers nearly all of their stars.

Freshness

Results are cached for 30 minutes on the server. GitHub's image proxy caches README images for about an hour, so new commits appear within roughly an hour.

FAQ

Questions from the clearing

Why can't I drag spirits inside my README?

GitHub shows README images through a proxy that strips all scripts. In the README the spirits wander on their own. Open the playground to drag, throw and startle them.

Why did a spirit wander off the edge?

Spirits roam beyond the frame on purpose, like animals leaving a clearing. They always come back.

How do I choose how many spirits appear?

The top 10 show by default. Add &limit=20 (or any number) to the image link, or &limit=all to show every repository.

Why does a spirit's commit count differ from my contribution graph?

The graph counts your own contributions per day. Spirits count every commit in a repository's default branch, by anyone.

Does my rank change?

Yes. It is recalculated from live data every time the image refreshes.
